## Overview

`MiraiTTSService` converts text into speech using [Mirai's](https://miraiminds.co)
streaming text-to-speech API, built for Indian languages: Hindi, Hinglish (Devanagari
with English words in Latin script) and Gujarati. Audio streams over HTTP with about
100 ms to first audio, at your pipeline's output rate, including 8 kHz for phone calls.

The package also includes:

- `MiraiSTTService`, for Mirai's streaming speech-to-text (see below): partial and
  final transcripts over one WebSocket, at 8 kHz as it comes off the phone.
- `MiraiRealtimeLLMService`, for Mirai's speech-to-speech Realtime API (OpenAI
  Realtime protocol). Speech recognition, turn detection, the model and the voice
  run together on Mirai's side, and this one service replaces STT, LLM and TTS.
- `apply_output_lead()`, which stops audio breaking up on phone calls over Pipecat's
  websocket transports when the bot's server is busy. It works with any TTS service.

## Installation

This is a community-maintained package distributed separately from `pipecat-ai`:

```bash
uv add pipecat-mirai
```

## Prerequisites

### Mirai Account Setup

Before using the Mirai text-to-speech service, you need:

1. **Mirai Account**: Sign up in the [Mirai console](https://sandbox.voice.miraiminds.co)
2. **API Key**: Create an API key (`sk_live_...`) in the console
3. **Voice Selection**: Choose `ashu`, `neha`, `shruti` or `sameer`

### Required Environment Variables

- `MIRAI_API_KEY`: Your Mirai API key for authentication

## Configuration

<ParamField path="api_key" type="str" default="None">
  Mirai API key. Defaults to the `MIRAI_API_KEY` environment variable.
</ParamField>

<ParamField path="settings" type="MiraiTTSService.Settings" default="None">
  Runtime-configurable settings: `voice` (default `"neha"`) and `model` (default `"mira-tts"`).
</ParamField>

<ParamField path="sample_rate" type="int" default="None">
  Output sample rate. Defaults to the pipeline's `audio_out_sample_rate`.
</ParamField>

<ParamField path="server_sample_rate" type="int | str | None" default="auto">
  Rate to ask Mirai for. `"auto"` asks for the output rate when Mirai serves it (8000,
  16000, 24000 or 48000 Hz); `None` keeps Mirai's default 48 kHz. Audio is resampled
  only if the rate Mirai sends differs from the output rate.
</ParamField>

<ParamField path="prebuffer_secs" type="float" default="0.15">
  Audio collected before an utterance's first frame is pushed, so a short first chunk
  followed by a pause doesn't start playback and then stall. `0` pushes audio at once.
</ParamField>

<ParamField path="warm_connection" type="bool" default="True">
  Open the HTTPS connection to Mirai when the pipeline starts, keep it open through
  pauses (`keep_warm_secs`, default 30 s), and reopen it after an interruption, so
  sentences don't wait for a TCP and TLS handshake.
</ParamField>

<ParamField path="base_url" type="str" default="https://sandbox.voice.miraiminds.co/v1">
  API base URL.
</ParamField>

## Usage

```python
from pipecat_mirai import MiraiTTSService

tts = MiraiTTSService(
    api_key=os.getenv("MIRAI_API_KEY"),
    settings=MiraiTTSService.Settings(voice="shruti"),
)

pipeline = Pipeline([
    transport.input(),
    stt,
    context_aggregator.user(),
    llm,
    tts,
    transport.output(),
    context_aggregator.assistant(),
])
```

### Phone calls

Pipecat's websocket transports send audio at exactly real time, so a stalled event
loop starves the phone provider and the caller hears the voice break. Let the
transport run slightly ahead:

```python
from pipecat_mirai import apply_output_lead

transport = FastAPIWebsocketTransport(websocket, FastAPIWebsocketParams(serializer=serializer, ...))
apply_output_lead(transport)  # up to 0.4 s ahead of real time
```

On 8 kHz Twilio-protocol calls with event-loop stalls, measured speech stretched by
breaks dropped from 6.6% to 0.08% at 3 concurrent calls and from 29.1% to 0.01% at 10.

## Speech-to-text

`MiraiSTTService` streams the caller's audio to Mirai's
`/v1/audio/transcriptions/stream` WebSocket and emits `InterimTranscriptionFrame` for
partial transcripts and one `TranscriptionFrame` per utterance, in order. It needs the
same `MIRAI_API_KEY`.

```python
from pipecat_mirai import MiraiSTTService

stt = MiraiSTTService(api_key=os.getenv("MIRAI_API_KEY"), language="hi-IN")

pipeline = Pipeline([
    transport.input(),
    stt,
    context_aggregator.user(),
    llm,
    tts,
    transport.output(),
    context_aggregator.assistant(),
])
```

<ParamField path="language" type="str | Language" default="hi-IN">
  `hi-IN`, `en-IN`, `gu-IN`, `mr-IN`, `pa-IN`, `bn-IN`, `ta-IN`, `te-IN`, `kn-IN` or
  `ml-IN`. Changes on the open socket.
</ParamField>

<ParamField path="model" type="str" default="mira-stt">
  Mirai's streaming model.
</ParamField>

<ParamField path="sample_rate" type="int | str" default="auto">
  The rate audio is sent at. `"auto"` sends an 8 kHz pipeline's audio as it is and
  resamples any other rate to 16 kHz. `8000` or `16000` forces one.
</ParamField>

<ParamField path="encoding" type="str" default="auto">
  `"auto"` (linear16), `"linear16"`, or `"mulaw"` / `"alaw"` (8 kHz only; half the bytes).
</ParamField>

<ParamField path="endpointing" type="str" default="auto">
  Who ends an utterance. `"manual"`: your pipeline's VAD. Its start and stop become
  `speech_start` and `speech_end` (with 0.5 s of audio from before the VAD fired, so
  the first word isn't cut), and nothing is sent between turns. `"vad"`: Mirai's VAD;
  audio streams continuously and the service proposes turn boundaries to the user
  aggregator. `"auto"` picks `"manual"` when the pipeline has a VAD.
</ParamField>

<ParamField path="edge" type="bool | str" default="auto">
  Open sockets on Mirai's STT edge, next to the GPUs, when it is offered, and on `url`
  otherwise. `False` always uses `url`. `MIRAI_STT_EDGE=off` turns it off for the process.
</ParamField>

<ParamField path="url" type="str" default="wss://sandbox.voice.miraiminds.co/v1/audio/transcriptions/stream">
  The streaming endpoint.
</ParamField>

<ParamField path="shared_pool" type="bool" default="True">
  Take a socket the process's pool opened ahead of need. `prewarm(stt_websockets=...)`
  or `MIRAI_WARM_STT_WEBSOCKETS` sets how many wait (2 by default).
</ParamField>

<ParamField path="settings" type="MiraiSTTSettings" default="None">
  Runtime-updatable settings: `language`, `model`, `stream_type` (`"fast"` or
  `"balanced"`), `mode` (`"transcribe"` or `"codemix"`) and, with Mirai's VAD,
  `threshold`, `silence_duration_ms`, `min_speech_duration_ms` and `prefix_padding_ms`.
</ParamField>

Time to first byte is reported from `speech_end` sent to the final, and usage as the
audio seconds sent. If the socket drops, the service redials once and replays the
audio Mirai hadn't answered (up to 30 s); a fatal error from Mirai arrives as an
`ErrorFrame`.
